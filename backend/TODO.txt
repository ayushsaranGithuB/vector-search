# ✅ Completed — E2E Pipeline

The full ingestion pipeline is implemented and working:

1. ✅ User uploads a PDF → `POST /uploads` creates source + presigned URL
2. ✅ File is saved to Cloudflare R2 → `POST /uploads/{id}/upload` (direct PUT) or `POST /uploads/{id}/finalize` (backend upload)
3. ✅ Task is added to Queue for ingestion into Pinecone → CloudAMQP `ingestion` exchange
4. ✅ Document metadata shows up in admin dashboard as "under processing" → auto-polling every 5s
5. ✅ A worker reads the queue and grabs the PDF, chunks and encodes it using Pinecone Inference into the correct project namespace
6. ✅ When the task is completed it is cleared from queue → message acknowledged
7. ✅ The PDF appears in dashboard as ready source → status = PROCESSED
8. ✅ Search works on frontend and can use this source for citations → hybrid search (vector + keyword)

# ✅ Modular URL Ingestion Pipeline

The URL ingestion pipeline is now a modular 4-stage pipeline:

1. ✅ **Fetcher** (`app/ingestion/fetcher.py`) — Uses `httpx` to fetch content, detects response `Content-Type`, handles redirects, timeouts, and HTTP errors with structured `FetchError` exceptions.
2. ✅ **Parser** (`app/ingestion/parsers/`) — Registry-based parser lookup by MIME type:
   - `HTMLParser` — Uses `readability-lxml` for article extraction + `BeautifulSoup` for cleaning
   - `PDFParser` — Uses `pypdf` for text extraction with metadata extraction
   - Register new parsers for new content types (DOCX, Markdown, YouTube, etc.) without pipeline changes
3. ✅ **Normalizer** (`app/ingestion/normalizer.py`) — Collapses blank lines, strips punctuation-only lines, normalizes Unicode whitespace.
4. ✅ **Chunker** (`app/ingestion/chunker.py`) — Paragraph-aware sliding window chunking with configurable size/overlap.

Shared models (`app/ingestion/models.py`):
- `Document` — Unified output model regardless of source type
- `FetchResult` — Raw fetcher output
- `ChunkResult` — Individual chunk with token count
- `PipelineResult` — Complete pipeline output

The pipeline is orchestrated by `app/ingestion/pipeline.py` (`run_pipeline()`), which chains all 4 stages and returns a `PipelineOutcome` with clear error reporting per step.
